# stdcell_gen: generated ics55 standard cell libraries

Two open standard cell libraries for ICsprout 55 nm (1.2 V core SVT devices `nm1p2_svt_lp` /
`pm1p2_svt_lp`), generated by [stdcell-gen](https://github.com/ckdur/stdcell-gen) (commit `9dcd1cd`,
`make -f Makefile.<lib> deliverable`, 2026-11-18). They are meant for place and route with LibreLane /
OpenROAD in this PDK, next to the vendor 7-track (`ics55_LLSC_H7C*`) and private 9-track libraries.

| Library | Height | Site | Cells | With liberty |
|---|---|---|---|---|
| `ics55t9` | 1.8 um (9 tracks of 0.2 um) | `obssite` 0.2 x 1.8 | 437 | 388 |
| `ics55t7` | 1.4 um (7 tracks) | `obssite` 0.2 x 1.4 | 405 | 354 |

Cell and pin names are the generator's (TSMC style): `ND2D1` (`a1 a2 -> zn`), `DFCNQD1`
(`d cp cdn -> q`), drive strength after `D`. `<lib>/cell_list` has the cells, and
`<lib>/doc/datasheet/index.html` documents every cell (function and table, pins, size, layout
picture, timing at tt).

## Contents

```
stdcell_gen/
  <lib>/                       # laid out like icsprout55/libs.ref/<lib>/
    gds/<lib>.gds.gz           # all cells, one top cell each (gzipped here, install.sh unpacks)
    lef/<lib>.lef              # SITE obssite + one MACRO per cell (pins, OBS); no tech layers
    liberty/<lib>_tt_1p20v_25c.lib.gz # NLDM, typical 1.2 V 25 C (gzipped)
    liberty/<lib>_ss_1p08v_125c.lib.gz  # slow 1.08 V 125 C
    liberty/<lib>_ff_1p32v_m40c.lib.gz  # fast 1.32 V -40 C
    verilog/<lib>.v            # functional models (power pins under `ifdef USE_POWER_PINS)
    verilog/<lib>_bb.v         # blackboxes
    cdl/<lib>.cdl              # LVS netlists (the ones the cells were LVS checked against)
    spice/<lib>.spice          # simulation netlists (MOS as X instances of the PDK model subckts)
    doc/datasheet/             # index.html + img/
    doc/verification/          # drc_lvs.txt (per cell), verilog.txt (models vs netlists)
    cell_list, README.md       # README: the status table of this build
  librelane/<lib>/config.tcl   # the draft library configuration as delivered (superseded by
  librelane/<lib>/synth_exclude.cells   #  icsprout55/libs.tech/librelane/<lib>, see below)
  librelane/<lib>/tracks.info
```

## What place and route needs to know

- **Technology**: use the PDK's tech LEF (`icsprout55/libs.tech/librelane/N551P6M_ecos.lef`); the
  layer names (`MET1`, `VIA1`, `MET2`, ...) match. The cell LEF only adds `SITE obssite` (both
  libraries use this name with different heights: do not load both in one design).
- **Power**: pins `VDD` (`USE POWER`) and `VSS` (`USE GROUND`), like the vendor libraries. Rails on
  MET1, 0.16 um high, centred on the bottom (VSS, y = 0) and top (VDD, y = height) edges of every cell;
  rows flip as usual.
- **Tapless cells**: no bulk contacts in the cells. Place `TAPCELL` (0.8 um wide) in every row at
  most ~50 um apart (latch-up rule LU_S_2 is 35 um from any source/drain to a tap). The cells were
  checked abutted (all cells in rows, alternate rows mirrored, fillers around, and TAPCELL columns that
  shift from row to row) with no DRC markers.
- **Fillers / ends**: `FILL1 FILL2 FILL4 FILL8 FILL16 FILL32 FILL64` (site multiples). No endcap cells:
  close the rows with fillers. `FILL1` alone has a MET1 minimum-area marker that disappears when
  abutted. Decaps: `DCAP DCAP4 DCAP8 DCAP16 DCAP64` (ics55t7 only).
- **Ties**: `TIEH/z`, `TIEL/zn`. **Antenna diode**: `ANTENNA/i`, in the liberty (junction
  capacitance 0.315 fF). Every signal pin of the LEF has `ANTENNAGATEAREA` / `ANTENNADIFFAREA`
  (extracted from the layout, the same areas as Magic's LEF writer).
- **Pins**: signal pins on MET1; 182 (ics55t9) / 167 (ics55t7) cells also have MET2 pin shapes and
  207 / 228 cells have MET2 obstructions (the cells route internally on MET2 where poly and MET1 are
  not enough), so MET2 is not free over every cell. The generator gives every port a place for the
  tech LEF's smallest VIA1 (a MET1 pad, MET2 kept off it) where it can; the VIA1 and higher cuts of
  the cells are OBS in the LEF. 32 (ics55t9) / 53 (ics55t7) cells still have a pin the OpenROAD
  detailed router cannot reach (DRT-0073) and are excluded, see below. `tracks.info`: 0.2 um, offset
  0 (the site pitch).
- **LVS**: the cells are LVS clean against `cdl/<lib>.cdl` with `icsprout55/libs.tech/klayout/tech/ics55.lvs`
  in `tapless=true` mode (wells tied to the rails). DRC: `ics55.drc`, clean except the density rules
  and the latch-up / floating well rules a single cell cannot satisfy.

## Liberty

- lctime (our fork) + ngspice with the PDK models (`ngspice/ICsprout_55LLULP1225_V1p1_hsp.lib`,
  sections `tt_mos`, `ss_mos`, `ff_mos`), 1 ps time step. Tables 6 x 6 like the vendor libraries:
  input slew 12 ps - 0.8 ns, output load 0.5 - 48 fF for a D1 cell, the loads above the first one
  multiplied by the drive strength (INVD8: up to 384 fF, BUFFD24: 1.152 pF).
- Limits: `max_capacitance` on every output pin = the top of its own load table;
  `default_max_capacitance` 1.152 pF, `default_max_transition` 0.8 ns.
- Content: input pin capacitances, delay and transition per arc, setup / hold / recovery / removal /
  minimum pulse width of the flip-flops, switching energy, leakage per input state
  (`cell_leakage_power`), `pg_pin`s, area from the LEF.
- **Not in the liberty** (exist in GDS/LEF/Verilog only, keep them out of synthesis): the latches and
  integrated clock gates (`LH*`, `LN*`, `CKLHQ*`, `CKLNQ*`: lctime cannot characterize latches), the bus
  holder `BHD`, and the physical cells (`FILL*`, `TAPCELL`, `DCAP*`; `ANTENNA` is in it, see above).
  `TIEH`/`TIEL` are in the liberty with their function but no timing or leakage.
- Also missing: the enable arcs of the tri-state buffers (`BUFTD*`: only `i -> z`), and the internal
  power of the flip-flops (OpenSTA reports 0 internal power for sequential cells).
- Some arcs of multi-stage cells have slightly negative delays at the fast corner with the slowest
  input slew (the output switches before the input reaches 50 %); OpenSTA accepts them.
- Checked on the previous build (c446888, same characterization flow with the old tables): every
  corner file loads in OpenSTA without warnings; corner order ff < tt < ss holds for every cell; a
  small counter synthesizes with yosys and passes STA and `report_power`. Not repeated on this build.

## LibreLane integration

`librelane --pdk icsprout55 --scl ics55t9` (or `ics55t7`).

- `install.sh` copies `stdcell_gen/<lib>` to `icsprout55/libs.ref/<lib>`, unpacks GDS and liberty and
  adds `spice/<lib>_lvs.spice`, the netgen reference (`hacking/magic/lvs_netlist.py`). Everything else
  is used as delivered: the cell LEF already has the antenna areas and `DATABASE MICRONS 1000`, the
  liberty the limits and the `ANTENNA` cell, the Verilog models no one-line `if` (which LibreLane's lint
  preprocessing deletes). The earlier fix-up scripts (`verilog_models.py`, `liberty_limits.py`, the
  antenna merge with `antenna.pins`) are gone.
- `icsprout55/libs.tech/librelane/<lib>/` (`config.tcl` sourcing `ics55t_common.tcl`, `tracks.info`,
  `synth_exclude.cells`) and a branch in the PDK `config.tcl`. Power pins `VDD` / `VSS`
  (`SCL_POWER_PINS`, `VDD_PIN`).
- `synth_exclude.cells` (also the PnR exclusion) has the physical cells, `BHD`, the latches / clock
  gates and every cell with a signal pin the OpenROAD detailed router has no access point for
  (DRT-0073), found by `hacking/pin_access_scan.tcl` (every cell placed in both row orientations, also
  stdcell-gen `test/pin_access.sh`): 32 cells of ics55t9, 53 of ics55t7 (164 / 138 on the previous
  build). 17 of the 20 flip-flops of ics55t9 and 16 of 18 of ics55t7 stay usable.

Fixed since the previous build (c446888), from the `demo_counter` findings:
- `PP_S_1` between the `TAPCELL`s of two rows on top of each other: TAPCELL fills its implants;
- `V1_W_1` (a router VIA1 on a VIA1 inside the cell): the cuts are OBS in the LEF;
- the pin access exclusions, as above.

`demo_counter` with either library (2026-11-18, run tags `debug_ics55t9` / `debug_ics55t7`):

| | ics55t9 | ics55t7 |
|---|---|---|
| Route DRC, LVS (Netgen, KLayout), antenna, power grid | 0 | 0 |
| Max slew / max capacitance violations | 0 / 0 | 0 / 0 |
| Setup / hold worst slack | 19.48 / 0.105 ns | 19.32 / 0.128 ns |
| Cells, std cell area | 771, 6336 um2 | 927, 6272 um2 |
| KLayout DRC | 6 | 5 |
| Magic DRC | 936 | 1254 |

KLayout DRC (sign-off): `CHIPEDGE_EN_1` (2, the die edge of the macro, as with the vendor 7-track
library) and
- ics55t9: `MET1_S_5` (4, all on pin `i` of `DEL005`): the router's VIA1 MET1 pad (0.17 high) on a
  routing track sticks out 0.02 um past the end of the 0.10 um pin, and the new line end is 0.09 um
  beside another MET1 shape of the cell (stdcell-gen STDCE-38);
- ics55t7: `M2_S_5` (3): MET2 line end spacing, not in the tech LEF rules.

Magic DRC reports only `NP_W_1` / `NP_S_1` / `PP_W_1` / `PP_S_1`, which KLayout does not (the Magic
hierarchy artefact also seen next to the vendor tap cells).

Still open: STDCE-38, `M2_S_5`, latches in the liberty (designs with latches do not synthesize), the
32 / 53 unreachable cells.

## Regenerating

In stdcell-gen (see its README, "Logic, Verilog and datasheet" and "Characterization"):

```
make -f Makefile.ics55t9 -j16 PYTHON3=<venv with lctime deps> CHAR_NGSPICE_DIR=<ngspice built --without-x> corners   # liberty (hours)
make -f Makefile.ics55t9 PYTHON3=<venv> deliverable                        # tmp/deliverable/ics55t9/
```

Open items are tickets in the `stdcell` workspace of bugs.ckdur.dev: STDCE-16 (views and
sign-off), STDCE-17 (pin access / site), STDCE-38 (DEL005 MET1_S_5 at a router via), STDCE-35 (latches), STDCE-36 (ties, tri-state enables,
flip-flop internal power), STDCE-33 (ics55f, the 12-track library, not characterized).
